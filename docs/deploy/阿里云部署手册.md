# MyPhone v0.1 正式环境部署手册（阿里云轻量应用服务器）

> 适用版本：myphone v0.1（master，commit `bee14a6` 及以后）
> 更新日期：2026-08-06
> 配套脚本：`deploy/` 目录（本手册与脚本一一对应）

## 0. 方案决策与已知限制

本次部署基于两点决策：

| 决策 | 结论 | 影响 |
|------|------|------|
| 域名/TLS | 暂无域名 | 先走 **IP + HTTP**（Nginx 前置 80 端口）。拿到域名后按第 11 节升级 HTTPS |
| TURN | 部署自建 coturn，客户端 ICE 已改为可配置 | 大陆环境通话可正常穿透 NAT |

> **★跨网络通话修复（2026-08 实机验证）：**
> 现象：两台手机分处 WiFi/移动数据(不同 NAT)时，"信令通但媒体不通、无法接通"。
> 根因链：① 手机(尤其国内运营商)常限制 App 的 **UDP 出站** → TURN(UDP 3478)不可用；② coturn 默认的 relay 端点间 IP 权限检查会**阻止 relay→relay 媒体转发**；③ ICE 可能选到不通的 host/srflx 候选。
> 修复（三者缺一不可）：
> 1. **coturn 加 `server-relay`**（取消 relay 端点 IP 权限检查，媒体可经 TURN 中继转发）—— 见 `deploy/coturn/turnserver.conf`
> 2. **APK 的 TURN URL 用 `turn:<IP>:3478?transport=tcp`**（TURN 走 TCP 绕过手机 UDP 限制）—— 见 `deploy/build.env.example`
> 3. **App 强制 `iceTransportPolicy=relay`**（媒体必走 TURN，避免 host/srflx 直连失败）—— `apps/mobile/lib/core/webrtc/webrtc_manager.dart`
> 另：coturn 需 `allow-loopback-peers` + 明确允许私有段，否则 host 候选 CreatePermission 会 403。

**必须知晓的限制（v0.1）：**
- 无 HTTPS 时信令（REST/WebSocket）为明文，理论可被中间人篡改。媒体通道本身仍是 DTLS-SRTP 端到端加密，且 App 有指纹比对。**正式商用前务必上 HTTPS。**
- TURN 采用静态凭据，凭据包含在 APK 内，可被逆向提取。已用 `total-quota`/`max-bps`/`no-loopback-peers` 限制滥用。后续可升级为 coturn REST API 动态票据（见 13 节）。
- 管理后台 `/admin` 目前无应用层鉴权，由 Nginx Basic Auth 保护。**不要绕过**（例如不要把 8080 端口暴露到公网）。

## 1. 生产架构

```
Android 手机 (App A) ──HTTPS/WSS 或 HTTP/WS──► 阿里云轻量服务器（公网 IP）
Android 手机 (App B) ────────────────────────►        │
                                                    Nginx  :80/443
                                            （反代 /v1、/ws、/admin）
                                                     │
                                              Go 信令服务 :8080（仅回环）
                                                     │
                                        ┌────────────┴────────────┐
                                   PostgreSQL :5432          Redis :6379
                                    （仅回环）              （仅回环）

   媒体通道（P2P，DTLS-SRTP）：App A ════ WebRTC ════► App B
   NAT 穿透：自建 STUN/TURN（coturn :3478，本服务器）
```

| 端口 | 用途 | 公网是否放行 |
|------|------|-------------|
| 22/tcp | SSH | 是（建议仅放行你的 IP） |
| 80/tcp | HTTP（Nginx 反代，当前主入口） | 是 |
| 3478/tcp+udp | TURN 控制 | 是 |
| 49152-65535/udp | TURN 中继 | 是 |
| 443/tcp | HTTPS（拿到域名后） | 是（预留） |
| 8080/tcp | Go 后端 | **否** |
| 5432/tcp | PostgreSQL | **否** |
| 6379/tcp | Redis | **否** |

## 2. 前置准备

1. **阿里云轻量应用服务器**（推荐 ≥ 2 vCPU / 2 GB，系统选 **Ubuntu 22.04/24.04**，本手册脚本对 Debian 系支持最完整；Alibaba Cloud Linux / CentOS 亦可，脚本会自动降级处理）。
2. **公网 IP**：轻量服务器默认有公网 IP，记录下来。
3. **开发机**：本仓库已 clone，具备 Go 1.22+ 与 Flutter SDK（`apps/server`、`apps/mobile` 均在本机构建过）。
4. 建议用密钥登录 SSH（控制台生成密钥对，SSH 时 `ssh -i 私钥 root@<公网IP>`）。

## 3. 阿里云控制台配置（一次性）

**轻量应用服务器控制台 → 防火墙（安全组）→ 添加规则：**

| 协议 | 端口 | 来源 |
|------|------|------|
| TCP | 22 | 你的办公 IP（或 0.0.0.0/0，配合密钥登录） |
| TCP | 80 | 0.0.0.0/0 |
| UDP | 3478 | 0.0.0.0/0 |
| TCP | 3478 | 0.0.0.0/0 |
| UDP | 49152 - 65535 | 0.0.0.0/0 |
| TCP | 443 | 0.0.0.0/0（预留，拿到域名后生效） |

⚠ **绝对不要放行 8080 / 5432 / 6379**——否则后端与管理后台将裸露公网。

## 4. 服务器初始化

把 `deploy/` 目录传到服务器（一次性）：

```bash
scp -r deploy root@<公网IP>:/root/myphone-deploy/
```

登录并安装依赖：

```bash
ssh root@<公网IP>
cd /root/myphone-deploy
bash install-deps.sh <公网IP>
```

脚本会：
- 自动识别 apt/dnf 发行版，安装 `postgresql` `redis-server` `nginx` `coturn` `apache2-utils`；
- 生成随机密码，写入 `/etc/myphone/myphone.env`（`DATABASE_URL`/`REDIS_ADDR`/`PORT`/`MYPHONE_DB_PASSWORD`/`MYPHONE_TURN_PASSWORD`/`MYPHONE_PUBLIC_IP`）；
- 启动 PostgreSQL / Redis；
- 写入 coturn 配置（账号 `myphone`，密码随机）并启动。配置文件路径按发行版自动选择：Debian 为 `/etc/turnserver.conf`，RHEL 系（Alibaba Cloud Linux/CentOS）为 `/etc/coturn/turnserver.conf`（systemd 单元固定读取）；
- 配置主机防火墙（ufw / firewalld，尽力而为）。

> 若无域名，脚本会尝试探测公网 IP 写入 `external-ip`。**把输出里的 `MYPHONE_TURN_CREDENTIAL` 记下来**，第 8 节打包 APK 要用。

## 5. 初始化数据库

```bash
bash init-db.sh
```

创建 PostgreSQL 角色 `myphone` 与数据库 `myphone`（幂等，可重复执行）。表结构无需手动创建——Go 服务端启动时自动迁移。

## 6. 服务端构建与部署

### 6.1 开发机：静态编译

```bash
bash deploy/build-server.sh
# 产物：deploy/artifacts/myphone-server（Linux x86_64 静态二进制，~8MB）
```

### 6.2 上传二进制

```bash
ssh root@<公网IP> 'mkdir -p /opt/myphone'
scp deploy/artifacts/myphone-server root@<公网IP>:/opt/myphone/myphone-server
```

### 6.3 服务器：部署服务

```bash
cd /root/myphone-deploy
bash deploy-server.sh
```

脚本会：
- 创建运行用户 `myphone`（nologin）；
- 安装 systemd 单元 `myphone.service`（`After` PostgreSQL/Redis，`Restart=always`，安全加固）；
- 启动服务并自检 `/health`；
- 生成管理后台 Basic Auth 凭据（账号 `admin` + 随机密码，**记下来**）写入 `/etc/nginx/.myphone-htpasswd`；
- 安装 Nginx 配置（`/etc/nginx/conf.d/myphone.conf`）并 reload。

> 改管理后台密码：`MYPHONE_ADMIN_PASSWORD=新密码 bash deploy-server.sh`（重跑即可）。

### 6.4 验证服务端

```bash
bash verify.sh
```

应输出：所有系统服务 active、`/health` 返回 `ok`、TURN/Redis 端口监听、端到端注册接口可用。

手动确认：

```bash
curl http://<公网IP>/health        # → ok
curl http://<公网IP>/v1/auth/login # → 405 或 JSON（说明 Nginx 转发正常）
```

## 7. 管理后台

- 地址：`http://<公网IP>/admin`
- 凭据：第 6.3 步生成的账号/密码（浏览器会弹出 Basic Auth 框）
- 功能：系统概览、用户管理（创建/禁用）、实时连接、通话记录 CDR、PreKey 密钥状态、服务状态。

> 注意：HTTP 下 Basic Auth 凭据以明文传输，仅限当前临时方案；上 HTTPS 后恢复安全。

## 8. 生产 APK 打包

### 8.1 填写本地配置

```bash
cp deploy/build.env.example deploy/.env.local
# 编辑 deploy/.env.local：
#   MYPHONE_SERVER_HOST = 公网 IP
#   MYPHONE_SERVER_PORT = 80          （当前 HTTP）
#   MYPHONE_SERVER_TLS  = false
#   MYPHONE_STUN_URL    = stun:公网IP:3478
#   MYPHONE_TURN_URL    = turn:公网IP:3478
#   MYPHONE_TURN_USERNAME   = myphone
#   MYPHONE_TURN_CREDENTIAL = install-deps.sh 输出的 TURN 密码
```

`.env.local` 已被 gitignore 忽略，不会入库。

### 8.2 打 Release 包

```bash
bash deploy/build-apk.sh
# 产物：apps/mobile/build/app/outputs/flutter-apk/app-release.apk
```

打包时会把服务器地址与自建 STUN/TURN 编译期注入 App（`--dart-define`）。未配置 TURN 的包会自动回退到 Google STUN + Metered 公共 TURN（仅适合开发联调，大陆不可用）。

### 8.3 分发与安装

- 直接发 APK 文件给测试用户安装（需允许"安装未知来源应用"）。
- 客户端要求：Android 7.0+，需授予通知权限（来电铃音）、麦克风权限（通话）。

## 9. 部署验收

| 项 | 方法 | 期望 |
|----|------|------|
| 服务端健康 | `curl http://<公网IP>/health` | `ok` |
| 管理后台 | 浏览器访问 `/admin` | Basic Auth 后可看概览 |
| 注册/登录 | 两台真机安装 APK | 注册、登录成功 |
| 在线状态 | 管理后台"实时连接" | 两台在线 |
| **通话** | **两台手机分别用 WiFi 与移动数据**，A 拨 B | 接通、双向语音、音质可接受 |
| 通话记录 | 管理后台"通话记录" | 出现 CDR（含码率/丢包/RTT） |
| NAT 穿透 | 双方都关 WiFi 用移动数据 | 走 TURN 中继也能接通 |

> 若移动数据下双方无法接通：检查安全组是否放行 `49152-65535/udp`，以及 `turnserver.conf` 的 `external-ip` 是否=公网 IP（`journalctl -u coturn` 查日志）。

## 10. 日常运维

### 10.1 日志

```bash
journalctl -u myphone -f          # 服务端实时日志（含 [AUTH]/[SIGNAL] 标记）
journalctl -u coturn -n 50        # TURN 日志
tail -f /var/log/nginx/access.log # Nginx 访问日志
```

### 10.2 状态 / 重启

```bash
systemctl status myphone
systemctl restart myphone         # 重启服务端（迁移会自动重跑，幂等）
systemctl restart coturn
```

### 10.3 备份（建议定时）

```bash
bash backup.sh                    # 手动备份到 /var/backups/myphone/，保留 14 份
```

加入 crontab（每天 03:00）：

```bash
crontab -e
# 0 3 * * * /root/myphone-deploy/backup.sh >> /var/backups/myphone/backup.log 2>&1
```

### 10.4 恢复

```bash
bash restore.sh /var/backups/myphone/db-20260806-030000.sql.gz
# 输入 YES 确认（会删除并重建 myphone 库），完成后 systemctl restart myphone
```

### 10.5 升级发布（服务端有新版本时）

```bash
# 开发机
bash deploy/build-server.sh
scp deploy/artifacts/myphone-server root@<公网IP>:/opt/myphone/myphone-server
# 服务器
bash deploy-server.sh
```

APK 有变化时，重跑第 8 节即可。

### 10.6 常见问题

| 现象 | 排查 |
|------|------|
| `verify.sh` 显示 myphone 未启动 | `journalctl -u myphone -n 50`，多为 DATABASE_URL 密码与库不匹配 |
| 注册返回 409 | 手机号已存在（服务端存的是哈希，重复注册即 409） |
| 手机提示无法连接服务器 | 确认 APK 用的 IP 与 `MYPHONE_SERVER_HOST` 一致；检查安全组 80 是否放行 |
| 通话接通即断 / 双向无声 | 多为 TURN 不可用：检查 3478、中继端口放行，`journalctl -u coturn` |
| 来电无铃音 | App 通知权限未授予 |
| 管理后台打不开 | 检查 `/admin` 是否走了 Basic Auth（浏览器记住旧密码可清缓存） |

## 11. HTTPS 升级（拿到域名后，强烈建议）

前提：域名已解析到服务器公网 IP（中国大陆服务器需完成 ICP 备案）。

```bash
# 1. 服务器：签发证书（certbot 自动改 Nginx 配置）
apt-get install -y certbot python3-certbot-nginx
certbot --nginx -d myphone.example.com

# 2. 服务器：确认 443 已放行（安全组添加 TCP 443）
# 3. 服务器：手动核对 conf.d/myphone.conf 是否保留了 /admin Basic Auth 与 WS 头
#    （certbot 可能改写了 server 块，必要时对照 deploy/nginx/myphone-https.conf 补齐）
nginx -t && systemctl reload nginx
```

重打生产 APK：

```bash
# deploy/.env.local 改为：
#   MYPHONE_SERVER_PORT=443
#   MYPHONE_SERVER_TLS=true
bash deploy/build-apk.sh
```

升级后管理后台地址变为 `https://myphone.example.com/admin`。Android 明文流量开关（`usesCleartextTraffic="true"`）此时可移除。

## 12. 安全清单（逐项核对）

- [ ] 安全组只放行 `22/80/3478/49152-65535`（+ 443），**无 8080/5432/6379**
- [ ] SSH 仅密钥登录，`PermitRootLogin` 已收紧或改用普通用户 + sudo
- [ ] 管理后台 Basic Auth 密码为随机强密码，未被透露
- [ ] `/etc/myphone/myphone.env` 权限 `600`
- [ ] PostgreSQL / Redis 仅监听回环（默认即如此，勿改 `listen_addresses`）
- [ ] 服务以 `myphone` 用户运行（systemd 单元已保证），非 root
- [ ] coturn 已开 `total-quota`/`max-bps`/`denied-peer-ip`（替代已废弃的 `no-loopback-peers`）/`no-multicast-peers`
- [ ] 每日备份 crontab 已配置
- [ ] （上线 HTTPS 后）App 不再走明文；`MYPHONE_SERVER_TLS=true`

## 13. 风险与后续硬化

| 项 | 现状 | 建议 |
|----|------|------|
| 信令明文 | 无域名，HTTP 临时 | 尽快备案域名切 HTTPS |
| TURN 静态凭据 | 凭据在 APK 内 | 后续改用 coturn `use-auth-secret`（REST API 动态票据，30s 过期），服务端加 `/v1/turn/credentials` 接口 |
| 管理后台鉴权 | 仅 Basic Auth | 后续可在 Go 层加 Admin JWT + 操作审计落库 |

| 备份异地 | 仅本机 | 定期把 `/var/backups/myphone/` 拉回本地或 OSS |

## 14. 实机部署发现的坑与修复（2026-08 实机验证）

以下问题在首次部署到 Alibaba Cloud Linux 3 时实机发现，**脚本已修复**，此处记录供排查参考：

| # | 坑 | 现象 | 修复 |
|---|----|------|------|
| 1 | PostgreSQL 未初始化 | `postgresql.service` 启动失败，报 `Directory "/var/lib/pgsql/data" is missing or empty` | RHEL 系 RPM 预建空 data 目录，`[ ! -d ]` 判断失效；改用 `[ ! -f /var/lib/pgsql/data/PG_VERSION ]` 判断，已回填 `install-deps.sh` |
| 2 | coturn 配置路径 | coturn 没起来、无 `/etc/turnserver.conf` | RHEL 系 unit 固定读 `/etc/coturn/turnserver.conf`；脚本现按发行版自动选择路径 |
| 3 | 密码算法不匹配 | `init-db.sh` 最后验证 `password authentication failed` | Alibaba Linux 默认 `password_encryption=md5`，而 pg_hba 改 scram。脚本改为 `SET password_encryption='scram-sha-256'` 后再建角色/重置密码 |
| 4 | coturn 日志无权限 | `Cannot open log file for writing` | coturn 以 `coturn`（RHEL）或 `turnserver`（Debian）用户运行；脚本现在 `touch` 日志并 `chown` 给对应用户 |
| 5 | `no-loopback-peers` 废弃 | `WARNING: Bad configuration format: no-loopback-peers` | coturn ≥4.5 已移除该选项，改用 `denied-peer-ip=127.0.0.0/8` |
| 6 | APK release 构建 R8 失败 | `Missing class com.google.android.play.core.splitinstall.*` | Flutter 引擎可选引用 play-core，R8 需 `-dontwarn`；已在 `proguard-rules.pro` 加规则 |
| 7 | JAVA_HOME 无效 | `JAVA_HOME is set to an invalid directory` | 本机 `JAVA_HOME` 指向不存在路径；`build-apk.sh` 已加自动探测 |

> 另：生产 APK 需用 **release 签名**（`key.properties` + keystore），不能用 debug 签名。key.properties 不入库，keystore 建议保存在项目外安全位置并备份。
